Forester · shape analysis with forest automata

Verifying C programs with trees,
skip lists and pointer reversal

Lists are hard for verification tools, and trees are harder. A heap that holds a tree, a skip list or a tree whose pointers are being rotated has no simple shape that a tool could guess. Forester represents sets of such heaps by forest automata. It explores all executions of a C program and either reports a memory error or proves that there is none, for data structures of any size.

How it works

  1. Compile. Clang translates the program to LLVM IR, which Code Listener (the front-end Forester shares with Predator) turns into a simple intermediate code.
  2. Execute symbolically. Starting from main, Forester runs the program on sets of heaps instead of single heaps. Unknown input, __VERIFIER_nondet_int() below, makes it follow both branches of every condition that depends on it.
  3. Represent heaps by forest automata. A heap is split at its cut-points, the nodes that are pointed to by a variable or by more than one pointer, into a tuple of trees. A tuple of tree automata then stands for a possibly infinite set of such heaps. Repeated substructures, like the inner lists of a list of lists, are folded into boxes, which Forester learns automatically.
  4. Abstract and check. Forester abstracts the automata until the sets stop growing. On the way it checks every dereference and every free, and it reports memory that becomes unreachable (garbage detected). If no error is found, it reports The program is SAFE.

binary tree

Destroying a binary tree without a stack

create() grows a binary tree of unknown shape: each round of the loop walks down a random path and hangs a new leaf on it. destroy() frees the tree without recursion and without extra memory: it repeatedly walks down to some leaf and frees it. Forester has to consider trees of every size and shape.

struct node {
    struct node *left;
    struct node *right;
};

/* a binary tree of unknown shape and size */
struct node *create(void)
{
    struct node *root = malloc(sizeof *root);
    root->left = NULL;
    root->right = NULL;

    while (__VERIFIER_nondet_int()) {
        /* walk down to a node with a free slot */
        struct node *n = root;
        while (n->left && n->right)
            n = __VERIFIER_nondet_int() ? n->left : n->right;

        struct node *leaf = malloc(sizeof *leaf);
        leaf->left = NULL;
        leaf->right = NULL;
        if (!n->left)
            n->left = leaf;
        else
            n->right = leaf;
    }
    return root;
}

/* remove leaves one by one, without recursion and without a stack */
void destroy(struct node *root)
{
    while (root) {
        struct node *parent = NULL, *n = root;
        while (n->left || n->right) {
            parent = n;
            n = n->left ? n->left : n->right;
        }
        if (!parent)
            root = NULL;
        free(n);
    }
}

skip list

Inserting into a skip list

A skip list keeps its nodes on several linked levels. Every node is on level 1, and some are also on level 2, so a search can skip ahead. Each level is an ordinary list, but the levels share their nodes, so the heap is neither a list nor a tree. insert() adds a node at an arbitrary position with an arbitrary height.

pointer reversal

Deutsch–Schorr–Waite tree traversal

The Deutsch–Schorr–Waite algorithm visits every node of a tree without a stack and without recursion: it rotates the child pointers of each node so that they temporarily point back up. After three visits, each node has its original children again. Garbage collectors use it because it needs no extra memory. It is also a classic challenge for verification tools, because during the traversal the heap does not look like a tree at all. This is the variant by Lindstrom, with a sentinel node.

{
    struct node *sentinel = malloc(sizeof *sentinel);
    struct node *n = root, *pred = sentinel;

    while (n != sentinel) {
        n->left = n->right;
        struct node *succ = n->left;
        n->right = pred;
        pred = n;
        n = succ;
        if (!n) {
            n = pred;
            pred = NULL;
        }
    }
    free(sentinel);
}

struct item {
    struct item *next;
    struct node *node;
};

void destroy(struct node *root)
{
    struct item *stack = malloc(sizeof *stack);
    stack->next = NULL;
    stack->node = root;
    while (stack) {
        struct item *top = stack;
        struct node *n = top->node;
        stack = top->next;
        free(top);
        if (n->left) {
            top = malloc(sizeof *top);
            top->next = stack;
            top->node = n->left;
            stack = top;
        }
        if (n->right) {
            top = malloc(sizeof *top);
            top->next = stack;
            top->node = n->right;
            stack = top;
        }
        free(n);
    }
}

    traverse(root);
    destroy(root);
    return 0;

#include <stdlib.h>

extern int __VERIFIER_nondet_int(void);

struct node {
    struct node *left;
    struct node *right;
};

struct node *create(void)
{
    struct node *root = malloc(sizeof *root);
    root->left = NULL;
    root->right = NULL;

    while (__VERIFIER_nondet_int()) {
        struct node *n = root;
        while (n->left && n->right)
            n = __VERIFIER_nondet_int() ? n->left : n->right;

        struct node *leaf = malloc(sizeof *leaf);
        leaf->left = NULL;
        leaf->right = NULL;
        if (!n->left)
            n->left = leaf;
        else
            n->right = leaf;
    }
    return root;
}

/*
 * Lindstrom's variant of the Deutsch-Schorr-Waite traversal: visits every node
 * without a stack, by rotating the child pointers.  After three visits, each
 * node has its original children back.
 */
void traverse(struct node *root)
{
    struct node *sentinel = malloc(sizeof *sentinel);
    struct node *n = root, *pred = sentinel;

    while (n != sentinel) {
        struct node *succ = n->left;
        n->left = n->right;
        n->right = pred;
        pred = n;
        n = succ;
        if (!n) {
            n = pred;
            pred = NULL;
        }
    }
    free(sentinel);
}

Forester and Predator

Forester and Predator come from the same group at Brno University of Technology and share their front-end. Predator is built for lists and is precise down to bytes: pointer arithmetic, block sizes, memset. Forester trades that precision for more general shapes: trees, trees with extra pointers, skip lists, and structures nested inside each other. Its ideas are in the papers Forest Automata for Verification of Heap Manipulation (CAV 2011) and Fully Automated Shape Analysis Based on Forest Automata (CAV 2013), which added the automatic learning of boxes.

Forester is a research prototype and has limits. It assumes that malloc succeeds (which is why the programs here do not check for NULL). It does not support stack-allocated structures whose address is taken. Some programs are beyond its abstraction: for example, destroying a tree by climbing back up through parent pointers gives a false alarm, and freeing a circular doubly linked list backwards did not finish in five minutes. Both are easy to try in the playground.

About this build. Forester was developed until 2020, as a GCC plug-in, in the Predator repository. The version on this page combines its last revision with a current Code Listener and its LLVM front-end, with small patches so that Forester understands the code that clang produces. All results on this page were recorded with the same WebAssembly build that runs in the playground. Every program is in cases/.
